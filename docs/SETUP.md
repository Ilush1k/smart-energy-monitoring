# Настройка и запуск

## Изолированный сценарий проверки

Начните с `compose.tests.yml`: он создаёт PostgreSQL в отдельном Docker-проекте и выполняет тесты на искусственных измерениях. Реальные подключения не требуются. Используйте уникальное имя `portfolio-energy-check`, чтобы не пересекаться с другими экземплярами приложения.

## Компоненты приложения

1. Подготовьте PostgreSQL и контракты источника/агрегатов. Схемы для тестового окружения создают fixtures в `adapter/tests/test_adapter.py`; SQL агрегатов лежит в `database/`.
2. Для Django скопируйте `.env.example` в `.env` в каталоге `Бэк/project_backend`, заполните свои подключения и запустите `python manage.py migrate`, затем `python manage.py runserver 127.0.0.1:5000`.
3. Для аналитики заполните `.env` из примера в её каталоге и запустите `uvicorn app.main:app --host 127.0.0.1 --port 8001`.
4. Для адаптера экспортируйте переменные из примера в окружение процесса. CLI сам не загружает `.env`. Один раз выполните `python -m adapter init-control`, затем `python -m adapter serve` из корня.
5. В frontend выполните `npm ci` и `npm run dev`. Vite проксирует `/api` на `127.0.0.1:5000`.

Токен вызова адаптера в Django и `ENERGY_ADAPTER_TOKEN` должны совпадать. Аналогично согласуйте `ANALYTICS_SERVICE_TOKEN` gateway и `ANALYTICS_INTERNAL_TOKEN` аналитики. Значения генерируются владельцем окружения, в примерах они пустые.

До смены рабочего расчёта энергии необходимо проверить/пересчитать исторические агрегаты и согласовать `ENERGY_USE_STORED_ENERGY` в обоих потребителях. Сам запуск нового адаптера не переключает автоматически семантику ранее записанных данных.

Публичная конфигурация предназначена для локальной разработки. Инструкции SSH, адреса рабочей сети, TLS-ключи и конфигурация действующих серверов сюда не включены.
